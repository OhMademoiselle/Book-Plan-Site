# План книги

Сайт-планировщик сюжета: несколько книг на одном аккаунте, в каждой вкладки (сюжет, герои, главы…), в них блоки (заголовок, текст, таблица, плашка, карточки героев с атрибутами, изображение). Данные хранятся в облаке Supabase и доступны с любого устройства. Сайт обычный статический: никакой сборки не нужно, его можно открыть как есть и выложить на GitHub Pages.

## Как обновить сайт на GitHub Pages

1. Откройте репозиторий на GitHub → **Add file → Upload files**.
2. Перетащите в окно **содержимое** папки с сайтом (файл `index.html` и папки `css`, `js`, `assets`, `supabase`, `tests`, файлы `README.md`, `.gitignore`). Папки нужно перетаскивать из проводника целиком: GitHub сохранит структуру.
3. Внизу нажмите **Commit changes**. Через минуту-две сайт обновится (на сайте нажмите Ctrl+F5).

Перед выкладкой разработчик запускает `npm run bump` (это ставит `?v=…` на файлы, чтобы браузеры не держали старые версии).

Если вы переходите со старой версии из одного файла, то после загрузки `index.html` заменится новым, а папки `css`, `js` и `assets` добавятся.

## Структура

```
index.html            страница: разметка, подключение стилей и скриптов, защита страницы (CSP)
assets/               иконки сайта (вкладка браузера, значок для iPhone)
css/                  стили, разбитые по частям страницы
  themes.css            цвета и темы оформления
  base.css              базовые стили
  header.css            шапка: логотип, меню книг, поиск, сохранение, настройки
  tabs.css              вкладки
  toolbar.css           панель «Настройки текста», меню добавления блоков
  blocks.css            блоки и карточки
  tables.css            таблицы
  overlays.css          окна, меню, уведомления, вход
  tour.css              обучение
  modes.css             режим чтения и выделение блоков
js/                   скрипты (подключаются по порядку, см. ниже)

tests/                проверки сайта (нужны только разработчику, для работы сайта не нужны)
```

### Скрипты и порядок подключения

Скрипты обычные (не модули) и работают как один общий файл, поэтому **порядок в `index.html` важен**: то, что выполняется сразу при загрузке, должно опираться только на файлы выше по списку.

| Файл | За что отвечает |
| --- | --- |
| `config.js` | адрес и публичный ключ Supabase (**единственный файл настроек**) |

| `state.js` | состояние: `S` (открытая книга и вкладка), `G` (облако), сохранение вида |
| `model.js` | модель данных: книги, вкладки, шаблон новой книги, проверка данных |
| `storage.js` | локальная база в браузере (IndexedDB): копия данных, кэш картинок, очередь отправки |
| `sanitize.js` | безопасная очистка HTML текста (`san()`, `plain()`) |
| `ui.js` | общие окна `modal` и сообщение `gm()` |
| `format.js` | форматирование текста: жирный, цвет, размер, шрифт |
| `clipboard.js` | копирование и вставка с форматированием |
| `blocks.js` | блоки: редактируемое поле `ed()` и отрисовка каждого типа (`R`) |
| `cards.js` | атрибуты карточек |
| `render.js` | отрисовка страницы: режимы, вкладки, блоки |

| `links.js` | ссылки на блоки |
| `multiselect.js` | выделение нескольких блоков и группы |
| `history.js` | отмена и возврат действий |
| `tables.js` | таблицы |
| `dnd.js` | перетаскивание |
| `block-actions.js` | копирование, очистка, дублирование блоков |

| `files.js` | файл резервной копии: скачивание и восстановление |

| `theme-boot.js` | подключается в `<head>` и применяет сохранённую тему до отрисовки |

### Словарь коротких имён

| Имя | Что это |
| --- | --- |
| `S` | состояние интерфейса: `S.books` (все книги), `S.tabs` (вкладки открытой книги), `S.active` (номер вкладки), `S.edit` (режим правки) |
| `G` | состояние облака: вход, версия данных, «есть несохранённое», ошибки |
| `h(тег, свойства, ...дети)` | создаёт элемент страницы |
| `ed(объект, ключ, класс, подсказка)` | редактируемое поле, привязанное к данным |
| `R` | отрисовщики блоков по типу (`R.cards`, `R.warn`…), `NEW` — шаблоны новых блоков |
| `upd()` | применить изменение вида: запомнить и перерисовать |
| `dataChanged()` | отметить данные изменёнными и запланировать отправку в облако |
| `pushNow()` / `pull()` | отправить данные в облако / получить |
| `kvGet` / `kvSet` | чтение и запись в локальную базу браузера |
| `san()` / `plain()` | очистка HTML / текст без разметки |

Ошибки в коде бросаются простыми объектами с признаком: `{net:1}` нет связи, `{auth:1}` нужно войти снова, `{conflict:1}` конфликт версий, `{http:код}` ошибка сервера, `{msg:'…'}` понятное сообщение для человека.

## Данные

Одна запись на аккаунт в таблице `plan_data`: `{ app, v: 4, saved, books: [{ id, name, tabs: [{ name, blocks: [...] }] }] }`. У записи есть номер версии: сохранение проходит только если версия не изменилась, иначе сайт показывает конфликт. Старый формат (`tabs` без `books`) открывается как одна книга «Моя книга». Картинки лежат в закрытом хранилище `plan-images`, у каждого пользователя своя папка; в данных хранится только имя файла.

## Настройка Supabase

1. В проекте Supabase откройте **SQL Editor** и выполните `supabase/setup.sql` целиком (повторный запуск безопасен).
2. В `js/config.js` должны быть адрес проекта и **публичный** ключ (`sb_publishable_…`). Секретный ключ сюда вставлять нельзя.
3. Тот же адрес проекта указан в защите страницы (`connect-src` в `index.html`). Если меняете проект, правьте оба места.
4. **Authentication → URL Configuration**: в Site URL и Redirect URLs укажите адрес сайта на GitHub Pages, иначе письма (подтверждение почты, сброс пароля) будут вести не туда.

## Безопасность

- Защита страницы (CSP) разрешает скрипты только с самого сайта (никаких встроенных скриптов) и запросы только к своему проекту Supabase.
- Данные каждого пользователя защищены правилами доступа в базе (Row Level Security): человек видит только свою запись и свою папку с картинками.
- Данные в облаке **не шифруются** на устройстве: владелец проекта Supabase технически может их прочитать. Это стоит знать и сказать пользователям.
- Текст блоков проходит через `san()`: остаются только разрешённые теги и стили.

## Проверки (для разработчика)

Нужен Node.js. Из папки `tests`:

```
npm install        один раз
npm run all        проверка порядка скриптов + линтер + все тесты
npm run check      порядок подключения скриптов
npm run lint       поиск ошибок и неиспользуемого кода
npm test           тесты в имитации браузера (вход, книги, редактор, картинки, обучение…)
npm run visual     снимки экрана в настоящем браузере (Chromium) для сравнения внешнего вида до и после правок
npm run format     привести код к единому оформлению (Prettier)
npm run bump       поставить новый номер версии на стили и скрипты (перед каждой выкладкой)
```

Если добавляете новый файл скрипта, подключите его в `index.html` в нужном месте списка и запустите `npm run check`.
